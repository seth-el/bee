# Memory lifecycle, Git review, and mutation journal

The ordinary general assistant exposes parent-owned `memory_edit`, `memory_forget`, and `memory_supersede` alongside memory search/show/remember. Edits use strict JSON and an expected version; only fields explicitly present in `fields` are changed. Forget appends the existing tombstone event. Supersession uses a local-store filesystem transaction: the complete replacement event log is written to a private temporary file, synced, atomically renamed, and only then reflected in memory. A failed transaction before rename leaves the prior log/state intact; directory fsync after rename is best-effort, so the rename is the logical commit point and power-loss durability follows the filesystem.

The assistant also exposes read-only `git_status` and bounded `git_diff`. Repository, path, and ref inputs are validated against the execution scope; Git is invoked with argv, never a shell string. A successful `git_diff` response always includes `repository`, `ref`, `path`, `has_changes`, `diff`, `truncated`, and `note`; an empty diff is represented as `has_changes: false`, not as an error. Truncated responses distinguish the requested capture limit from the potentially shorter returned prefix required by the bounded JSON envelope, then recommend increasing the limit when possible, narrowing the path, or continuing from the partial diff rather than repeating unchanged arguments. These tools never apply, merge, reset, checkout, or otherwise mutate Git state.

The separate source-only bounded local Git mutation slice is documented in
[bounded-git-mutations.md](bounded-git-mutations.md). It adds exact-path
`git_stage`, read-only `git_staged_review` with a cryptographic review hash,
and guarded local-only `git_commit`; it does not widen generic command or Git
authority.

Built-in `write_file` mutations are journaled by the default composition below the injected session-store root, in a scope-hashed private journal directory. The tool has four operations: `create`, `append`, `edit`, and `replace`. An omitted operation means create-only and refuses to touch an existing file. Append preserves every existing byte, edit replaces exactly one `old_text` match, and whole-file replacement must be requested explicitly. Append, edit, and replace optionally accept the current file's `expected_sha256` and fail before writing when it is stale. Journal entries include bounded path, timestamps, before/after existence, size, SHA-256, mode, and result metadata. Modified-file preimages are owner-only and bounded. `mutation_list`, `mutation_show`, and hash-guarded `mutation_undo` are available to the general assistant. Undo refuses to overwrite a later human/model edit. Created files are deleted on successful undo; modified files are restored with their recorded mode.

The journal uses a process lock plus a conservative owner-only cross-process lock. Each scope gets a separate on-disk root below the injected journal base. Journal JSONL and preimages share one bounded quota and entry count; incomplete/orphan preimages are removed during replay. The journal commit itself is crash-safe as an immutable replacement of the journal file, but a process crash between the file rename and evidence commit can leave a file change that is not represented; the tools fail closed on evidence-commit errors and attempt immediate reversion.

Limitations: arbitrary `run_command`, terminal tools, extensions, child processes, external processes, and non-file side effects are not journaled and are not automatically reversible. Compatibility registries created directly with `NewGeneralAssistantRegistry` remain unjournaled unless a journal-aware composition is used; `ComposeGeneralAssistant` supplies the default private journal.
