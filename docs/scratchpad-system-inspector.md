# Scratchpad and system inspector

> **Not model-facing since 2026-11-12.** The main assistant no longer offers the tools below (`scratch_*, process_list, process_info`) (`prunedForegroundTools` in `assistant.go`; usage review in AGENTS.md). They remain implemented and tested, and restoring one is a one-line change.

Bee's ordinary assistant includes two bounded slices:

- `scratch_set`, `scratch_get`, `scratch_list`, and `scratch_delete` are a private TTL scratchpad separate from session JSONL history and durable memory. The narrow `scratch_set` and `scratch_delete` writes are explicit plan-gate exceptions so they can support mid-task state; normal policy and prompted-mode approval still apply. Entries are automatically scoped to the durable session bound to the run context; tool arguments cannot select a session. Values are owner-only, atomically replaced, cross-process locked, bounded to 64 entries / 256 KiB per session, and expire after 1 second to 7 days (default 1 hour). Expired entries are pruned lazily on scratch access; there is no background sweeper. Missing or deleted durable-session context fails closed. Scratch values are never promoted to durable memory automatically; the assistant may explicitly read a value and then use the normal, user-authorized `memory_remember` flow.
- On Linux, `process_list` and `process_info` inspect only processes owned by the current UID using bounded `/proc` status data. They do not expose environment variables, full command lines, open-file contents, or credentials.
- On Linux, `service_list`, `service_status`, and `service_logs` inspect only user-level systemd services. Unit names must be literal `.service` names. Commands use retained trusted absolute executables under `/usr/bin` or `/bin`, direct argv execution with `--user` and no pager, a finite command-output cap, and a small environment allowlist with fixed `PATH=/usr/bin:/bin`; no mutation or service-control operation is exposed. Non-systemd hosts retain process tools but omit service tools. Non-Linux compositions omit these tools.

The inspector is intentionally not part of locked mode because locked mode has no executor. Compatibility adapters and child projections do not gain host inspection authority unless their parent explicitly includes the tools in an allowlist. Tests should inject `ScratchpadStore` and `SystemInspector` rather than touching live `~/.bee` state.
